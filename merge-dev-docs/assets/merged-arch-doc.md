## 架构分册的四条约束

1. **组件图、类图、字段清单不写正文。** 改成指向源码路径或设计稿链接，这些内容合并当天就过期。
2. **每个「为什么」都要有出处。** 没出处的理由说明是合并时自己脑补的，删掉。
3. **待确认项必须能回答「谁来定、什么时候定」。** 答不出来的降级到盲区清单。
4. **不写命名规范、目录落位、评审清单。** 那是开发规范分册的内容，写在这里就是两份文档重新分裂的开始。
