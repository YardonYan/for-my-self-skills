# 阶段一：逐页稿

逐页稿是这套流程的核心产物。它把「一堆资料」变成「每页说什么」，后面的风格、制作、打磨全部以它为准。

## 7 个字段

| 字段 | 定义 | 常见错误 |
|---|---|---|
| 标题 | 这一页的核心观点，不是栏目名 | 写成「市场分析」而不是「华东是唯一正增长区域」 |
| 想表达的意思 | 这页要让观众理解什么，一句话 | 和标题重复，没有增量 |
| 屏幕文字 | 真正放在页面上的精简文案 | 把整段正文搬上去 |
| 数据与来源 | 对应文件、页码或链接 | 只写数字不写来源，后面核不了 |
| 图片素材 | 文件名及用途 | 写「配一张图」，没指定文件 |
| 建议布局 | 文字、图片、图表如何组织 | 空着，或写「美观即可」 |
| 演讲备注 | 不必显示在屏幕上的补充 | 和屏幕文字重复 |

## 生成逐页稿的提示词

复制下面这段，把方括号换成实际内容：

```
请阅读我上传的内容说明、原始资料和图片素材（或访问该项目的本地文件目录）。本轮只整理内容，不生成 PPT、不生图。

先用几句话复述你理解的：这份 PPT 给谁看、用于什么场合、核心观点是什么，以及希望观众看完记住什么。

请区分几类材料的用途：
- 原始资料：用于提取信息、核对事实
- 正式素材：用于后续页面展示
- 风格参考：仅用于视觉，其中的文案和数据不得直接引用

如果缺少会影响核心观点、内容取舍或事实准确性的信息，先集中列出需要我补充的问题。其他不影响主线的缺项，可以标注"待补充"，继续整理。

然后按照我提供的页数、顺序和逐页要求，整理成逐页稿。如果我没有指定分页，请结合演讲时长建议页数和顺序，并简要说明安排逻辑。

每页写清楚：
1. 标题：优先表达这一页的核心观点
2. 想表达的意思：这一页要让观众理解什么
3. 屏幕文字：实际放在页面上的精简文案
4. 数据与来源：注明对应文件、页码或链接；没有则不填
5. 图片素材：写出要使用的文件名及用途；缺少则标注待补充
6. 建议布局：简要说明文字、图片或图表如何组织
7. 演讲备注：放不必全部显示在屏幕上的补充说明

允许精简表达，但不能改变原意，不得补造数字或事实。
必须保留我明确指定的内容；如建议调整，请单独说明。
资料有冲突、内容有重复、某页太挤，请具体指出并给出建议。
不要为了凑页数添加空泛章节，也不要把所有资料都塞进 PPT。

最后汇总需要我确认或补充的事项。等我确认逐页稿后，再进入设计。
```

## 写作规则

- **标题写观点**：「Q3 复购率下滑 6 个点」比「运营数据」有用
- **一页一件事**：一页塞两个观点，观众两个都记不住
- **屏幕文字和演讲备注分开**：写不下的一律进备注
- **数据必须带来源**：单位、口径、时间范围，缺一个都不算合格
- **冲突要指出不要自己裁决**：两份材料数字不一致时列出让用户定
- **不凑页数**：宁可 12 页讲透，不要 20 页各讲一点

## 文件格式

`verify.py` 按下面的格式解析，用模板生成可以保证格式对：

```markdown
# 逐页稿

## 第 1 页

- **标题**：一句能独立成立的观点
- **想表达的意思**：这页要让观众理解什么
- **屏幕文字**：
  页面上实际出现的文字，多行就换行缩进。
- **数据与来源**：报告.pdf 第 12 页 / 无
- **图片素材**：`01_cover.png`（封面主图）/ 待补充
- **建议布局**：左侧主图占三分之二，右侧三行要点
- **演讲备注**：这里写不显示在屏幕上的补充

## 第 2 页
...
```

字段名必须与上表完全一致，`- **字段**：` 前缀不要改，否则校验不认。

## 校验口径

```bash
python scripts/verify.py script <项目目录>
```

检查四件事：

1. 页码从第 1 页开始连续，不重复不跳号
2. 每页 7 个字段齐全且非空
3. 统计「待补充」数量，提醒还有哪些缺口
4. 字段名拼写正确（写成「布局」而不是「建议布局」会报缺失）

输出 `RESULT: PASS` 才能进阶段二。有问题会逐条列出文件、页码和字段。

## 常见返工原因

| 现象 | 根因 | 改法 |
|---|---|---|
| 做完发现页数不够讲 | 简报没写讲时 | 补讲时，让 AI 重排页数并说明逻辑 |
| 每页都被改 | 逐页稿只有标题，没有布局和素材 | 用精致型简报重写该页 |
| 数据和原文对不上 | 逐页稿没记来源 | 回原始资料补来源，再核一遍 |
| 图片反复换 | 逐页稿写「配一张图」 | 指定具体文件名和用途 |
