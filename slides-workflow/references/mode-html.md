# 模式一：HTML Slides

用代码在网页里做幻灯片。适合现场演示、需要动画和交互、想放一点技术表现的场合。

## 什么时候选它

- 要现场讲，翻页要顺、要有动画
- 需要交互：分步展开、方案切换、可点击的目录
- 想做得比静态 PPT 有表现力
- 不介意交付物是网页而不是 pptx

不适合：对方只接收文件、必须在他人电脑上用 PowerPoint 打开、需要多人协作编辑。

## 可选的外部 Skill

下面三个是社区里针对 HTML 演示场景的 Skill，原文工作流里用过。它们不是本仓内容，装不装、用哪个按你的环境和需求定：

| Skill | 侧重 | 什么时候先试它 |
|---|---|---|
| frontend-slides | HTML 演示文稿，风格预览、固定 16:9 画布 | 普通分享、主题演讲 |
| huashu-design | 幻灯片、原型、动画、信息图 | 内容需要大量图片图解与动态演示 |
| visual-explainer | 流程、架构、数据与技术概念可视化 | 关系与机制需要讲清楚 |

没有这些 Skill 也能做，把下面的提示词直接给模型即可，只是少了预置的风格参考库。

## 制作提示词

```
请使用 [选定的 Skill]，根据已确认的逐页稿、风格说明和正式素材，制作一套 HTML Slides。

用于 [演示场合]，面向 [目标受众]。
直接完成整套，保持原有内容逻辑与页序，
不新增未经资料支持的事实、数字或结论。

一、页面与视觉
采用固定 16:9 画布，在不同窗口尺寸下整体等比缩放，不能拉伸、裁切正文，或让页面内容溢出。不要做成需要上下滚动阅读的长网页。
标题和正文使用真实 HTML 文字，图表、流程和示意图尽量使用可渲染的元素，不要把整页图片当作 HTML 幻灯片。
沿用已确认的风格，统一配色、字体层级和页脚。根据内容调整构图，避免每页套同一种卡片布局。

二、演示与交互
支持左右键翻页、上一页和下一页按钮、全屏及页码。提供目录或概览，方便现场跳转到指定页面。
动画只用于解释顺序、状态变化和突出重点。需要交互的页面，可以使用分步展开、方案切换等方式，但不能让关键内容只能通过悬停才能看到。操作后应能返回初始状态，方便重复演示。

三、离线与备用材料
优先交付可本地打开、断网使用的版本，将必要的图片、字体和脚本一并打包，不依赖外部 CDN 或临时图片链接。
如果必须启动本地服务，或某项功能需要联网，请提前说明，并给出明确的打开方式。
同时导出 PDF 备用稿，一张幻灯片对应一页。PDF 中展示动画和交互页面的完整关键信息，不要出现空白、隐藏内容或演示控制按钮。

四、检查与交付
在浏览器中检查全部页面的文字、图片和交互，测试翻页、全屏、窗口缩放、页面跳转和断网重开。修正文字溢出、元素遮挡、图片丢失等问题。
交付入口 HTML、完整素材文件夹和 PDF 备用稿，整理到同一文件夹中，并告诉我从哪个文件打开、需要什么运行条件，以及还有哪些已知限制。
```

## 把参考图一起给

除了 `style-spec.md`，把参考图本身也放进上下文。文字化的风格说明会损失信息，图能补回来。两者同时给，比只给其中任何一个都准。

## 现场演示前必测

| 项目 | 怎么测 | 不合格的表现 |
|---|---|---|
| 翻页 | 左右键、按钮、目录跳转各走一遍 | 翻到某页卡住或跳错 |
| 缩放 | 把窗口从最大拖到一半 | 文字被裁、元素重叠、出现滚动条 |
| 全屏 | F11 与内置全屏各试一次 | 上下留黑边、内容偏移 |
| 断网 | 拔网线刷新 | 图片消失、字体回退变形 |
| 投影 | 接一次投影仪或外接屏 | 小字看不清、深色区发灰 |

投影这一项最容易被跳过，也最常在现场出事。电脑上看着舒服的字号，投到会议室的幕布上可能小一半。

## 验收清单

- [ ] 固定 16:9，窗口缩放时等比缩放，无裁切、无溢出、无滚动条
- [ ] 标题正文是可选中复制、可搜索的真实文字
- [ ] 左右键、按钮、页码、目录跳转都正常
- [ ] 动画只用于解释，不干扰阅读
- [ ] 全部资源本地化，断网可开
- [ ] 一页一屏的 PDF 备用稿已导出，动效页保留了完整信息
- [ ] 入口文件、素材目录、PDF 在同一文件夹
- [ ] 明确告知打开方式与已知限制
