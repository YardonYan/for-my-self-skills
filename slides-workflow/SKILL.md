# slides-workflow — 从素材到成稿的幻灯片生产流程

一句话总纲：内容先行，形态后选。先把「要说什么」定死，再定「长什么样」，最后才决定做成 HTML、整页图片，还是可编辑 PPTX。

## 为什么是这个顺序

做 PPT 的时间看起来都花在排版上，但真正决定返工次数的是一开始的信息是否定清。内容没定稿就开始排版，改一句文案就要动一次版式；风格没统一就开始逐页做，改着改着会像几套 PPT 拼在一起。

所以流程是：**采集 → 逐页稿 → 风格说明 → 制作 → 局部打磨**。前两步是硬闸，不确认不往下走。

## 四个阶段

| 阶段 | 产出 | 过闸条件 |
|---|---|---|
| 一 采集与逐页稿 | `page-script.md` | 用户确认逐页稿，`verify.py script` 通过 |
| 二 风格说明 | `style-spec.md` | 用户选定一个方向 |
| 三 选形态并制作 | 成品 + 备用稿 | 按所选形态的验收清单逐条过 |
| 四 局部打磨 | 定版 | 检查清单全过 |

阶段一和阶段二结束都要停下来等确认。跳过闸门的代价不是省时间，是后面按倍数返工。

## 阶段一：采集与逐页稿

### 先问清六件事

写进简报，缺一项就问，不要猜：

1. 给谁看、什么场合
2. 希望对方看完记住什么（一句话）
3. 大概讲多久（决定页数）
4. 必须出现哪些内容
5. 预计页数
6. 有没有硬性限制（品牌色、模板、必须保留的原文、不许出现的内容）

### 简报分两型

| 类型 | 写到什么程度 | 适用 |
|---|---|---|
| 简洁型 | 上面六件事 + 大类素材 | 课堂汇报、趣味展示、内部交流 |
| 精致型 | 六件事 + 逐页要展现什么，甚至布局与结构 | 正式汇报、要反复改、对风格有要求 |

精致型才是省时间的那个。AI 会按自己的理解分页、写文案、选图，不做硬性限制，最后就要反复改。举个写到位的例子：

> 第 4 页：介绍咖啡店秋季上新的三款饮品。使用我提供的三张饮品照片，每款标注名称、价格和一句口味介绍，具体信息以菜单为准，不要自行添加销量或"最受欢迎"等描述。标题、价格和介绍文字需要保留为可编辑文本。布局可由 AI 决定，以图片清晰、三款饮品方便对比为准。

### 素材分三个目录

```
assets/
├── raw/        原始资料：报告、论文、数据表，用于核对事实
├── final/      正式素材：产品截图、活动照片、Logo，用于页面展示
└── reference/  风格参考：截图、设计稿、别人的成品页
```

必须提前说明：原始资料里的内容不一定都要进 PPT，风格参考里的文案和数据也不代表可以直接用。AI 混用这两类是最常见的错误。

### 逐页稿

按 7 个字段逐页写。字段定义、写作规则和校验口径见 `references/page-script.md`，模板见 `assets/page-script.md`。

简报的填写方法与素材准备清单见 `references/brief.md`；两种简报的空白模板是 `assets/brief-simple.md` 与 `assets/brief-full.md`，`scaffold.py` 会把它们复制进项目目录。

| 字段 | 写什么 |
|---|---|
| 标题 | 优先表达这一页的核心观点 |
| 想表达的意思 | 这页要让观众理解什么 |
| 屏幕文字 | 实际放在页面上的精简文案 |
| 数据与来源 | 对应文件、页码或链接；没有则不填 |
| 图片素材 | 文件名及用途；缺少标「待补充」 |
| 建议布局 | 文字、图片、图表如何组织 |
| 演讲备注 | 不必显示在屏幕上的补充说明 |

三条底线：允许精简表达但不能改变原意；不得补造数字或事实；必须保留用户明确指定的内容，如需调整单独说明。

## 阶段二：风格说明

用参考图，不要只用文字描述。「米白底色、大标题」这种描述，十个人能做出十个样子；一张图能让 AI 直接看到结构。

参考图从哪来：Pinterest、SlidesCarnival、Slideland、prezman、Awesome DESIGN.md 这类站点，或用户自己的旧稿与设计稿。

拆解方法见 `references/style-spec.md`，产出 `style-spec.md`。四个要点：

1. **区分观测与建议**：哪些是图里能明确看到的，哪些是根据内容提出的设计建议，分开写
2. **字体不猜**：无法确认的字体不要写成确定名称，给气质接近且支持中文的替代
3. **多方向而不是换色**：给几个构图明显不同的方向，只换配色不算方向
4. **按使用场景改**：投屏、电脑阅读、打印三种场景对字号和对比度的要求不同。参考图里的小字、低对比、过密排版如果不适合当前场景，要指出并调整

## 阶段三：选形态并制作

### 决策表

| 你的情况 | 选哪种 | 走哪份说明 |
|---|---|---|
| 现场讲，要动画或交互，不怕技术门槛 | HTML Slides | `references/mode-html.md` |
| 只想先看效果，或者只发给人看 | 整页图片 | `references/mode-image.md` |
| 后续还要频繁改，或要交给同事继续改 | 可编辑 PPTX | `references/mode-pptx.md` |
| 有必须遵循的企业模板 | 可编辑 PPTX，直接沿用母版 | `references/mode-pptx.md` |
| 封面要视觉冲击，内容页要能改 | 混用：封面与重点页生图，其余可编辑 | 两份说明拼用 |

### 三种形态的硬约束

**HTML Slides**：固定 16:9 画布等比缩放，不拉伸不裁切不溢出，不做成长网页；标题正文用真实 HTML 文字，不用整页图片冒充；支持左右键翻页、全屏、页码、目录跳转；动画只用来解释顺序与状态；离线可开；同时导出 PDF 备用稿。

**整页图片**：一页一图，16:9，不生成样机、屏幕、多页拼图；文字直接在图里且投屏能看清；按 `01_封面`、`02_页面标题` 命名；不擅自改画产品截图、人物、Logo；生成后逐页核对文字数字，再按序合 PDF。

**可编辑 PPTX**：标题正文页码用真文本框；图表用带可编辑数据的原生图表，不用形状拼外观冒充；表格可增删行列；流程图节点、文字、连线分别可编辑；图片可保留但标题正文标注要独立；有模板就沿用母版版式。先做三页样稿，确认后再整套。

### 图片稿还原成 PPTX

只有后续还要频繁改才值得做。图片里的文字已经和画面融在一起，还原要重新识别、拆分、排版，未必能同时做到完全一致和全部可编辑。

用混合还原：标题、正文、标签、关键数字、页码做可编辑文本框；简单色块线条用原生形状；复杂照片插画保留为独立高清图片；要更新数据的图表用原始数据重建。

铁律：文字转文本框后必须清除背景里的原文字，不许整页截图铺底再盖文本框冒充可编辑。拆不干净的区域保留图片形式并在交付说明里标明，不要强行补画造成失真。

## 阶段四：局部打磨

第一版大概率不达标，这一阶段决定最终质量。指令要具体，五段式：

```
只修改第 [N] 页，以我提供的实际打开截图为依据。
问题：[实际看到的问题]
希望改成：[具体结果]
允许修改：[布局、字号、图片大小等范围]
需要保留：[满意的设计、原文、数值、其他页面]
```

三条纪律：

- **先判断原因再改**，不要为了修一个局部问题重做整页或整套
- **同一问题连续两轮没改善就停下查原因**，不要继续重复生成
- **改完重新检查整页**，确认原问题解决、且没有新增遮挡或溢出

如果是可编辑 PPTX，有些小细节自己改更快；如果是 HTML 或图片，要控制改动边界，不要让 AI 自由度太大。

五段式指令的逐段解释、不同形态的改动边界、交付前检查清单，以及什么时候该停手不再打磨，见 `references/revision.md`。

## 已知失败模式

| 症状 | 处置 |
|---|---|
| AI 自行分页，最后反复改 | 简报里把页数、页序、逐页要求写死，走精致型 |
| 参考图的小字低对比投屏看不清 | 阶段二就按场景指出并调整，不要照搬参考图 |
| 图片稿还原后文字不可编辑 | 生图前先确认后续要不要改；要改就直接走可编辑模式 |
| 整页截图铺底冒充可编辑页 | 明确禁止；交付说明逐页标注仍是图片的部分 |
| 修一个局部问题被重做整页 | 修改指令限定「只改第 N 页」并列出允许修改范围 |
| 同一问题两轮没改善 | 停下查原因，继续重复生成只会更远 |
| 无法确认模型或版本 | 如实说明，不要凭提示词声称已切换模型 |
| 图表要更新数据但没有原始数据 | 不猜数值，明确说明编辑限制 |
| 有些素材无法准确使用 | 说明限制，不要生成近似图片冒充原素材 |

## 脚本

```bash
python scripts/scaffold.py <项目目录>            # 生成简报、逐页稿、风格说明三个骨架 + 素材目录
python scripts/verify.py script <项目目录>        # 校验逐页稿完整性，输出 PASS / 问题清单
python scripts/verify.py assets <项目目录>        # 校验素材命名与逐页稿引用是否对得上
```

两个脚本只用 Python 标准库，不联网。`verify.py` 的验收口径写在 `references/page-script.md`。

## 交付清单

无论哪种形态，交付时都说清四件事：

1. 从哪个文件打开、需要什么运行条件
2. 成品清单（入口文件、素材目录、PDF 备用稿）
3. 哪些要求没做到，原因是什么
4. 还有哪些已知限制

## 不做的事

- 不做没有任何素材的凭空创作。素材不够时先要材料，不要硬编内容
- 不做企业模板的像素级复刻。要严格遵循品牌模板时，人做比 AI 快
- 不承诺交付物必须联网才能放映
- 不把「图片看起来对」当成「内容正确」，数字与单位必须回到原始资料核
