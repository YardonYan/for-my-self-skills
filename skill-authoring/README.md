# skill-authoring — 造 Skill 的调研与提炼

> 调研脏，写得再漂亮也是给错的东西排版；提炼软，产出的就是把常识换个说法。

## 解决什么

造 Skill 最容易出两种废品，而且从成品表面都看不出来。

一种是**调研偏了**。只看本人著作，得到的是他想让你看到的版本；只看外部评价，得到的是别人眼里的他；只看最近的动态，把一时的表态当成一以贯之的立场。材料选偏，后面每一步都在放大偏差。

另一种是**提炼软了**。三十条候选论点全写进去，读者看完记不住任何一条；把「要长期主义」这种谁都会说的话包装成独特洞察，一戳就破；只收正面材料，产出的视角没有盲区，反而最危险。

这个 Skill 只管两件事：把调研切干净，把提炼做狠。3 个有证据的模型，强于 10 条正确但没信息量的原则。

## 什么时候用

```
帮我做一个芒格的视角 Skill，重点是他怎么看投资决策。
把我们的生产校验流程整理成一份 Skill，材料我打包给你。
这个 Skill 说它有 15 个官方示例全是 A 级，帮我看看这个结论靠不靠谱。
我要把一堆 issue 和复盘整理成能装的 Skill，从哪开始。
```

## 三个可复用的方法

| 方法 | 用在哪 | 核心 |
|---|---|---|
| 六路调研 | 调研阶段 | 原始论述、对话即兴、措辞表达、外部评价、决策行为、时间线近期，六个方向各落一份文件，缺一路就偏 |
| 三重验证 | 提炼阶段 | 跨域复现、生成力、排他性，三关全过才算模型；过一到两关降为启发式；一关不过直接丢弃 |
| 失败降级表 | 写作阶段 | 触发条件 → 一线修复 → 仍失败兜底，三列写清已知会挂的场景，没写过的位置就是没跑过 |

## 工作流

1. 定源：确认要处理的是人物、主题还是文档集，确认有没有一手材料
2. 六路调研，每一路落盘到 `references/research/01` 到 `06`，标注一手、二手、推断
3. 提炼：候选论点过三重验证，按过关数分流到模型、启发式、丢弃
4. 写 SKILL.md：填失败降级表、设三处检查点、写具体到能指导决策的诚实边界
5. 验收：已知题、边缘题、风格题各跑一遍，两轮不过就把薄弱项写进边界后交付

## 附带的两份清单

- **评估现成 Skill 的六问**：信息密度、失败降级、结论可溯源、自检可信度、可移植性、合规。前五条看它好不好用，第六条看它能不能进公共库
- **反模式八条**：编造原话、常识包装成洞察、只收正面材料、信息不足硬写、关键词统计当自检、路径写死、检查点变阻塞、处理真人材料不提示同意

## 边界

| 能力 | 状态 |
|---|---|
| 调研维度切分与提炼筛选 | ✓ 核心能力 |
| 失败降级表与自检设计 | ✓ 核心能力 |
| 评估第三方 Skill 的可信度与合规 | ✓ 六问清单 |
| 排版美化、模板套用 | ✗ 不是它的职责 |
| 替你做内容判断（这个观点对不对） | ✗ 只给证据标准，判断权在人 |
| 绕过版权与授权拿材料 | ✗ 明确列入反模式 |

## 安装

```bash
git clone https://github.com/YardonYan/for-my-self-skills.git
cp -r for-my-self-skills/skill-authoring <your-agent-skills-dir>/
```

或让 Agent 自己装：

```
帮我安装这个 skill：https://github.com/YardonYan/for-my-self-skills/tree/main/skill-authoring
```
