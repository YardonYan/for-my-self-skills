# 微信会剥掉什么

公众号编辑器不是浏览器。粘进去的 HTML 会过一层清洗，理解它删什么，才知道排版该写成什么样。

## 必删清单

| 被删的东西 | 后果 | 正确写法 |
|---|---|---|
| `<style>` 标签 | 全部样式失效，退成纯文本 | 每个标签写内联 `style=""` |
| `class` / `id` 属性 | 选择器失效 | 不要依赖类名，样式直接写在元素上 |
| `<script>` | 交互全废 | 不写脚本 |
| 外链 `<link>` | 字体、图标不加载 | 用系统字体栈 |
| 非白名单标签 | 标签被拆掉，只留文字 | 用 `section` `p` `span` `strong` `em` `img` `table` `br` |

`<pre>` 是灰色地带：标签能留，但 `white-space: pre-wrap` 经常被吃掉，代码块就挤成一行。所以脚本用 `<section>` + `<br>` 分行，而不是 `<pre>`。

## 图片的三层过滤

这是最容易踩的地方，逐层看：

**第一层，本地路径不解析。** `<img src="images/a.png">` 在编辑器里没有来源可读。

**第二层，外链被过滤。** 即使给了 `https://gitee.com/.../a.png`，微信也会拦。除了域名白名单，还有 Referer 防盗链——第三方图床会直接返回 403。

**第三层，只认自家图床。** 正文里能显示的图片，地址必须是 `mmbiz.qpic.cn`。要拿到这个地址，只能调 `media/uploadimg`。

结论：**图片必须在推送前上传换地址，没有捷径**。这也是为什么"图片粘过去就消失"这件事反复出现——大部分工具只做了排版，没做图片迁移。

## 两条路线

### 路线 A：convert 后手动粘贴

1. `python scripts/wmp.py convert article.md -o 公众号版.html`
2. 浏览器打开这个 HTML
3. `Ctrl+A` → `Ctrl+C`
4. 编辑器里 `Ctrl+V`

图片会跟着剪贴板一起过去，微信会把它们重新上传一次。样式偶尔被改写一两处，比如 `border-radius` 掉了、`letter-spacing` 被忽略——这是可接受的损耗。

适合：账号未认证、不想交出 AppSecret、偶尔发一篇。

### 路线 B：push 进草稿箱

1. `python scripts/wmp.py push article.md --cover cover.png --author ... --digest ...`
2. 脚本依次：取 token → 上传正文图 → 上传封面 → `draft/add`
3. 打开后台草稿箱，预览，**自己点发布**

适合：账号已认证、要稳定样式、想省掉粘贴。

## 排版约束

写 HTML 或写 Markdown 时守住这些，能少改很多轮：

- 正文 16px，行高 1.9，字距 0.4px。手机上这是舒服区
- 小节标题用左竖线而不是只有加粗，扫读时层级更清楚
- 代码块字号 13px，配 `word-break: break-all`，长行才能折
- 表格最多 3 列。4 列以上手机上必然挤，改成卡片或列表
- 图片满宽 + 圆角，图注 12.5px 居中灰字
- 不要用渐变、阴影、emoji 当图标

## 发布前检查

`python scripts/wmp.py check 公众号版.html` 会查这些：

- 有没有 `style` / `script` / `link` 残留
- 有没有 `class` / `id`
- 除结构性标签外，每个元素是否都带内联样式
- 图片是本地文件还是微信图床
- 正文中文字数是否逼近 20000

`RESULT: PASS` 才算能发。
