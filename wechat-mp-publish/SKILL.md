# wechat-mp-publish — Markdown 进，草稿箱出

一句话总纲：AI 负责写和排，人负责两件事——审稿，以及点发布。

## 要解决的真问题

公众号发布卡人的地方不是排版，是图片。

Markdown 里写 `![封面](images/cover.png)`，粘进公众号编辑器，图全丢，只剩一个裂开的图标或链接。原因有三层，缺一层都不行：

| 层 | 发生了什么 | 解法 |
|---|---|---|
| 本地路径 | `images/cover.png` 在微信编辑器里无法解析 | 图片必须先有公网地址 |
| 外链地址 | 微信会过滤非自家域名的图片，还有 Referer 防盗链 | 域名必须是 `mmbiz.qpic.cn` |
| 自定义图床 | 挂到 Gitee、OSS 上也不认 | 只能先传到微信自己的图床 |

所以 `.html` 文件传不上去、图片粘过去消失，都不是操作问题，是链路问题。这个 Skill 把链路补全：**每张图先走 `media/uploadimg` 换成微信地址，再写进正文**。

## 四步流程，两个人工闸门

```
AI 写稿(md) ──► [人审稿] ──► AI 排版+传图 ──► [人发布]
                  闸门1                        闸门2
```

**闸门一：审稿。** 内容没定就别排版。排完再改稿，图片要重传一遍。

**闸门二：发布。** 工具只把文章送进草稿箱，永远不替你点发布。这条是硬规则，不是能力限制。

## 命令

只依赖 Python 3.8+ 标准库，不用 pip install。

```bash
# 1) 看排版效果，不联网、不需要凭据
python scripts/wmp.py convert article.md -o 公众号版.html --theme qing
python scripts/wmp.py check 公众号版.html

# 2) 先干跑一遍，确认图片和字段都没问题
python scripts/wmp.py push article.md --cover cover.png --author Yardon --dry-run

# 3) 真推草稿箱（需要 .env 里的 AppID / AppSecret）
python scripts/wmp.py push article.md --cover cover.png --author Yardon --digest "摘要"

# 4) 凭据和连通性自检
python scripts/wmp.py doctor
```

`convert` 产出的是可粘贴 HTML，图片保留原地址；`push` 才会上传图片换成微信地址。

## 两条出口怎么选

| 情况 | 走哪条 |
|---|---|
| 账号未认证，或不想给程序 AppSecret | `convert` → 浏览器打开 → 全选复制 → 粘到编辑器 |
| 账号已认证，想省掉手工粘贴 | `push` → 后台草稿箱看一眼 → 点发布 |
| 只想要稳定样式，不在乎自动化 | `convert` + 固定主题，粘贴 |

`convert` 出来的 HTML 粘贴时图片会跟着走（浏览器会把图像数据放进剪贴板），但样式可能被微信改写一两处；`push` 没有这个问题，因为 HTML 是直接从服务端写进草稿的。

## 主题

`assets/themes.json` 里三个：`qing`（青竹，深青）、`ink`（墨黑）、`blue`（经典蓝）。

改这个 JSON 就能加新主题，不用动代码。换主题只影响配色和字号，不影响结构。

## 微信的字段上限

写稿阶段就要守住，别等接口拒绝：

| 字段 | 上限 | 超了会怎样 |
|---|---|---|
| 标题 | 32 字 | 接口报错 |
| 作者 | 16 字 | 接口报错 |
| 摘要 | 128 字 | 45004 |
| 正文 | 20000 字 | 40008 |
| 正文单图 | 1MB，仅 jpg/png | 上传失败 |
| 封面 | 10MB，建议 2.35:1（900×383） | 上传失败 |

脚本会在推送前替你卡这几项。

## 排错

| 现象 | 原因 | 处置 |
|---|---|---|
| `40164` | 调用 IP 不在白名单 | 后台「设置与开发 → 基本配置 → IP白名单」加当前公网 IP。运营商 NAT 的 IP 会变，建议跑在固定 IP 的机器上 |
| `40007` | 封面用了临时素材 | 封面只能走 `material/add_material`，不能用 `media/upload` |
| `48001` | 接口未授权 | 草稿箱接口需要公众号完成微信认证，未认证的个人订阅号调不通，改走 `convert` 粘贴 |
| `40008` | 正文过长 | 拆篇，或压缩代码块 |
| `45004` | 摘要超 128 字 | 删短 |
| 草稿里图片裂开 | 正文图不是 `mmbiz.qpic.cn` | 走 `push`，别手工拼外链 |
| Mermaid 变成一堆代码 | 微信不渲染 Mermaid | 先导出 png，再用 `![](图)` 引用。`convert` 会直接报错拦住 |
| 代码块挤成一行 | `<pre>` 的换行样式被剥离 | 脚本已用 `<section>` + `<br>` 分行，不要改回 `<pre>` |

## 关于发布接口

`freepublish/submit` 是真正把文章发出去的接口。2025 年 7 月起，**个人主体和未认证企业号的发布权限已被回收**，只有认证的服务号/订阅号能调用。

所以本 Skill 的定位是明确的：**机器负责生产与入库，人负责放行**。这不是妥协，草稿箱本身就是个安全缓冲区——进去了还能改、能预览、能挑时间。

## 不做的事

- 不代替用户点发布，也不做定时群发
- 不做小红书、知乎等平台的排版（各家过滤规则不同，混做会两头不讨好）
- 不替你写稿。写稿交给写作类 Skill，这里只管把稿子送到位
- 不在没有审稿的情况下推送。`push` 之前人必须看过 `convert` 的产物
