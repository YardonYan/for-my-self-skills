# 阅读体验层：让人读得下去

> 禁用词零命中、句子干净，不代表读得下去。
> 这一层管的是「读者会不会在第三段就走」。
> 来源：2026-10-22 评一篇 9,862 字的技术实测文。信息质量 A，阅读体验 B。

## 一、读不下去的四个真实原因

不是错字，不是术语。是下面这四个。

### 1. 数字过载

每 200 字一个精确数字，读者记不住，也感受不到。

一篇 9,862 字的文章里，单是第二节不到 800 字就出现 13 个精确数字：353ms、396ms、8 条、48,089 字、0.5 秒、20.6 万字……读到最后，一个也留不下。

**改法：数字分级。**

| 层级 | 处理 |
|---|---|
| 主数字 | 支撑结论的那个，每节留 2 到 3 个 |
| 次要数字 | 降级成「差了一个数量级」「差不多快一倍」 |
| 佐证数字 | 放进表格，想深究的人自己看 |

判断标准：**删掉这个数字，结论还站得住，它就是次要的。**

### 2. 结论给得太早

每节第一段就亮答案，读者没有「想知道」的驱动力。悬念被提前抽掉，剩下的只有验证。

**反例**

> 打开它，一次请求返回的 50 条结果里，每一条都自带正文全文。

**正例**

> 打开它之后，返回体比预期长了很多。
>
> 点开第一条看，`content` 字段里是整篇文章。再看下一条，也是。五十条，每条都有。
>
> 我本来只想试试 `count` 能不能开到 50，没想到顺手把正文也拿回来了。

差别不在字数，在于**读者是跟着你发现，还是被你通知**。

### 3. 节奏太均匀

每节都是「现象 → 数据 → 表格 → 结论」。读到第三节，读者已经知道套路，期待感归零。

**改法：允许有一节不讲数据。** 讲一个故事、一个判断、一段态度。全文至少一节是纯人话。

哪一节最适合？通常是讲开源项目、讲人、讲取舍的那一节。

### 4. 情绪线是平的

全程冷静记录，读者也跟着平。

**改法：每两三千字至少一处情绪外露。** 四种都行：

- 不确定：「我以为是接口在骗我」
- 自嘲：「包括我前面那个 103」
- 意外：「运行完愣了一下」
- 态度：「这种项目值得认真说一句谢谢」

技术文不需要煽情，但需要**你有反应**。你无动于衷，读者也无动于衷。

## 二、加粗是稀缺资源

一篇 9,862 字的文章原本有 101 处加粗，收敛到 39 处之后，重点才显出来。

**全文正文加粗不超过 15 处。** 超过这个数，强化效果归零。

| 值得加粗 | 不值得加粗 |
|---|---|
| 核心判断 | 表格里的数字 |
| 反直觉的结论 | 列表项的引导词 |
| 要读者记住的那一句 | 方案标签（「方案 B：」） |
| | 语气强调（「成本太高」） |

**自检方法：把全文加粗的地方连起来读，应该是一篇完整的摘要。**
如果连起来读是一堆碎片，说明加粗用滥了。

## 三、开头三种写法

按效果排序：

1. **场景型**（最好）：具体画面加反常现象。「我盯着一个 404 看了很久。」
2. **数字型**（次好）：一个让人意外的数字先行。「先说个数字：37 秒。」
3. **信息型**（最差）：「X 月 X 日，某公司发布了某产品。」

这是新闻通稿的写法。信息型不是不能用，但**不能当第一句**，要放在场景或数字之后。

## 四、表格是核对工具，不是叙述工具

- 表格前后必须有文字承接，不能两块表挨着
- 能用一句话说清的两列对比，不要做成表
- 表格里的数字可以精确，正文里的数字要分级

**判断表格是否过密的正确方式**：统计「表格块」的数量，不是数 `|---` 的出现次数。代码块里的表格语法会被算进去，导致误判。

## 五、自检清单（写完必过）

- [ ] 全文正文加粗不超过 15 处，连起来读是一篇摘要
- [ ] 每节主数字不超过 3 个
- [ ] 开头第一句是场景或数字，不是「X 月 X 日」
- [ ] 至少有一节完全没有数据，纯人话
- [ ] 至少三处情绪外露（不确定、自嘲、意外、态度）
- [ ] 没有两块表格挨在一起
- [ ] 自己读第一遍时，有没有想往下看的冲动

最后这条最准。**你自己都不想往下看，读者更不会。**

## 六、和 L1 到 L4 的关系

四层自检管的是「写得对不对」，这一层管的是「读不读得下去」。

两层都要过。一篇结构完整、风格到位但读不下去的文章，等于没写。
